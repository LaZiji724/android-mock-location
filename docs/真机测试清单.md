# 真机与微信测试清单（荣耀 200 Pro / 华为 nova 5z）

每项记录测试日期、设备型号、Android 版本、MagicOS 版本、微信版本和截图或诊断文本。尚未操作的项目记为“未测试”，不要标为通过。

1. 用 `adb devices -l` 确认设备为 `device`，读取 `ro.product.model`、`ro.build.version.release`、`ro.build.version.sdk` 和 MagicOS 版本信息。
2. 安装 `app-debug.apk` 和 `probe-debug.apk`，启动两个 App，确认无闪退。检查地图瓦片、缩放、拖动、选点、标记与路线显示。
3. 在手机开发者选项选择“安卓改定位”为模拟位置信息应用，回到主 App 确认已授权。
4. 固定定位选一个与真实位置相距明显、但安全易识别的坐标。记录主 App 目标、诊断页的最近提交位置和时间。在独立读取器点“读取系统 GPS”，记录坐标、`isMock` 与精度。两者应在精度范围内一致。
5. 停止模拟，再用独立读取器读 GPS。待真实 GPS 获得定位后，确认不再是先前的模拟坐标；必要时到室外等待卫星定位。
6. 手动添加至少两个路线点，启动、暂停、继续、中途改速并等到终点；定时记录独立读取器位置，确认朝终点变化。检查路线完成后保持终点，直到停止。
7. 进入摇杆，按住正东与东北方向，查看独立读取器位置变化。松开、切换页面和返回，确认不再移动；在路线中切换摇杆后测试“继续原路线”和“保持当前位置”。
8. 保存、改名、删除收藏；保存、加载路线；从历史记录选点。重启 App 后确认数据仍在。
9. 模拟过程中切到其他 App、锁屏、等待，再检查通知和独立读取器。测试通知栏“停止模拟”。检查系统电池管理是否需要对本 App 允许后台运行，并记录系统实际行为。
10. 断开 USB，重新从桌面启动主 App、开始模拟、切换后台，再由独立读取器确认。记录结果。
11. 微信“发送位置”：固定点模拟时打开微信，记录微信地图实际显示的位置。若不同，记录独立读取器结果并尝试等待定位刷新，区分系统问题、缓存或微信处理。
12. 经参与者知情同意，在两台设备上启动微信实时位置共享。接收端记录固定点显示位置；启动路线后记录接收端位置是否随时间变化；切后台后再记录。保留微信版本和测试时间。

如果手机尚未连接，或微信双设备操作尚未发生，上述项目均不得写为已验证。不要修改微信安装包或绕过其模拟位置检测。

## 华为 nova 5z（SPN-AL00，HarmonyOS 3.0）补充项

0.2.1 起支持。以下各项同样未测试前记为“未测试”。

13. 从 GitHub Release 下载 0.2.1 主 APK 安装，记录是否遇到纯净模式、未知来源或安全检测提示及处理方式。确认能安装、能打开、地图能显示（Kirin 810 / Mali-G52）。
14. 首次打开是否自动弹出配置向导；诊断页“系统”一行是否显示 HarmonyOS 与 Android 10 (API 29)。
15. 逐项点向导按钮，记录每个按钮实际跳到的页面，特别是“应用启动管理”是否直达列表页、“去允许”是否弹出后台运行对话框。完成后返回，确认状态自动变为已完成。
16. 固定定位后，用 GPS 读取器分别读 GPS 和网络定位，两者都应是模拟坐标；诊断页“模拟提供者”应为“GPS + 网络”。关闭“同时模拟网络定位”后重新开始，确认变为“仅 GPS”，并记录网络定位读到的是否为真实位置。
17. 路线模式运行中锁屏 10 分钟和 30 分钟，再解锁查看位置是否持续前进、通知是否还在；分别在完成和未完成后 4 项推荐配置时各测一次。
18. 多任务界面一键清理后（已锁定 / 未锁定），模拟是否仍在运行。
19. 停止模拟后，GPS 读取器读到的 GPS 与网络定位是否恢复真实位置。
20. 华为地图、高德、微信“发送位置”分别显示的位置，记录 App 版本。

## 2026-10-22 华为 nova 5z（SPN-AL00，HarmonyOS 3.0 / Android 10 API 29）实机记录

版本 0.2.2（versionCode 5），USB 调试 + `adb`，macOS。以下按第 1–20 项的可执行部分记录，未执行项仍为“未测试”。

### 已确认：系统层注入生效

- `appops get com.example.androidmocklocation android:mock_location` 返回 `MOCK_LOCATION: allow`。
- 开始固定定位后 `dumpsys location` 显示 `gps provider [mock]` 与 `network provider [mock]`，`Last Known Locations` 为提交坐标；停止后两个 provider 恢复为普通状态，无残留。
- 独立读取器读取 `GPS_PROVIDER` 得到提交坐标，`系统标记为模拟: true`；网络定位返回同样的模拟坐标。
- 地图点选、输入框直接输入经纬度两条改坐标路径都生效；运行中再次提交会立即更新。
- 系统杀进程留下测试提供者后，重新打开 App 会清理残留，之后能正常启动（0.2.2 的 `Provider "gps" already exists` 修复项复现验证通过）。

### 目标 App 实测

- **高德地图 17.01.0**：采纳模拟坐标。`dumpsys location` 可见其每秒请求 `gps`；logcat `LocationProxy: ... is mock location: true`；地图“我的位置”随模拟点跳转（上海 → 北京），跨城市验证通过。
- **微信 8.0.79**：发送位置与共享实时位置均显示真实位置，不采纳系统模拟坐标。系统层仍是 mock（`dumpsys location` 与 logcat 一致），所以不是注入失败。
  - 微信自带腾讯定位 SDK（APK 内 `com.tencent.map.geolocation`、`libtencentlocsapp.so`、`com.tencent.mm.plugin.location_soso`），并自带 `com.tencent.mm:locationservice` 进程；实测关闭 WLAN 后仍显示真实网络定位，说明其定位结果来自腾讯自己的网络定位/融合，而不是系统 provider。
  - 系统测试提供者提交的 `Location` 会带 `isMockProvider` 标记，普通应用无法清除；本项目不修改微信、不隐藏模拟标记。
  - 结论：微信不采纳属于已知限制，不是 0.2.2 的注入缺陷。

### 未测试

- 锁屏/后台保活 10–30 分钟、多任务一键清理、断 USB 后台运行、路线/摇杆长时间运行、停止后真实定位恢复。
- 微信双设备实时位置共享接收端表现（需第二台设备）。
- 荣耀 MagicOS 设备。

## 2026-10-23 微信模拟定位验证（0.3.0，同一台 nova 5z）

设备无 SIM 卡，仅连 WiFi；模拟点北京 `39.904200, 116.407400`，真实位置上海（约 1100 公里外），便于区分。

### 结论

- **微信 8.0.79“发送位置”**：开启“网络定位拦截（微信模式）”→“拦截腾讯定位域名”后，强制停止微信再打开，地图定位到北京王府井/东单，绿点为模拟点，地点名显示“东城区东单台基厂头条10号院”。
- **微信 8.0.79“共享实时位置”**：发起共享后，共享地图上的本人头像标记位于北京王府井/台基厂，界面显示“你正在共享位置”。聊天、图片、腾讯地图瓦片均正常。
- **不开拦截时**：发送位置仍显示上海真实网络定位，证明差异来自 DNS 拦截而不是缓存或误差。
- **高德地图**：不需要拦截，直接采纳模拟坐标。

### 关键日志

- 被拦截的域名：`I/DnsShield: BLOCK lbs.map.qq.com`（微信打开位置时连续 2 次尝试）。
- 微信同期解析的其他域名（未拦截，地图和聊天用）：`vectorsdk.map.qq.com`、`vectorsdk-cn.map.qq.com`、`pr.map.qq.com`、`apisec.map.qq.com`、`apikey.map.qq.com`、`overseactrl.map.qq.com`、`analytics.map.qq.com`、`szminorshort.weixin.qq.com`、`pull-x*.wxlivecdn.com` 等。
- VPN 建立后 `ip addr show tun0` 为 `inet 10.111.222.1/32`，仅路由 `10.111.222.2/32`；`ping lbs.map.qq.com` 返回 `unknown host`，其余域名正常解析。

### 说明

- 原理是腾讯定位 SDK 拿不到 `lbs.map.qq.com` 的网络定位后回退到系统 GPS 测试提供者；不需要隐藏 `isMockProvider` 标记，也不需要 root。
- 微信会缓存 DNS，开启拦截后必须先强制停止微信；微信以后更换定位域名时，用“只记录 DNS 查询”模式抓新域名补进名单。
- 共享实时位置的接收端未用第二台设备复核；本次只确认发起端地图显示模拟坐标。
